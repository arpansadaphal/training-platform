### ARCH-039 — A successful `commitFromMutation` runs the same TrainingBlock close + open sequence as `activateVersion`; all three lifecycle triggers apply the same COMPLETED / ABANDONED resolution rule and read inside their own transaction
Date: 2026-09-26 | Status: FROZEN | Reversible: Yes, contained to `packages/api/src/services/programVersionService.ts`, `trainingService.ts`, `programService.ts`, and their shared reads in `packages/db/src/repositories/trainingBlock.ts`
Decision: Three coupled lifecycle rules applied by all three trigger points: (1) **commitFromMutation runs the close + open.** Every successful commit — via `commitFromDraft` or `commitFromSimulation` — closes the Program's current ACTIVE TrainingBlock (if any) and opens a new ACTIVE block against the newly written ProgramVersion, inside the SAME transaction that writes the version, revision, snapshot, and flips activeVersionId. (2) **Close-status resolution is uniform.** A closing block becomes COMPLETED iff it has ≥1 Session with status = COMPLETED; otherwise ABANDONED — applied identically at `activateVersion`, `commitFromMutation`, and `archiveMyProgram`. (3) **Reads run inside the writing transaction.** New tx-aware read variants `findActiveTrainingBlockForProgramInTx` and `countCompletedSessionsForBlockInTx` exist for this; the non-tx variants remain for read-only callers.
Rationale: (a) The phase-06 file's narrower reading predates Phase 4's activeVersionId pointer flip; a commit IS activation. Leaving commit outside the lifecycle produces an actively broken state (active version, no block, `getOrCreateNext` has nowhere to put a Session). (b) Archive's literal wording would force a successfully-trained block to read as abandoned. (c) commitFromMutation's pre-transaction-check-plus-DB-catch precedent (Phase 4/5) does NOT apply to TrainingBlock: `@@unique([programId, versionNumber])` catches a racing commit, but TrainingBlock has no equivalent unique constraint — a partial unique index `WHERE status = 'ACTIVE'` cannot be expressed in Prisma's schema DSL. Inside the transaction is the only mechanism.
Alternatives considered: (1) Keep commit outside the lifecycle — rejected. (2) Add a third commitFromMutation call site — rejected; invariant 2. (3) Pre-transaction check on activateVersion — rejected; no DB-level catch. (4) Archive forces ABANDONED unconditionally — rejected; misleads history.
Consequence: The invariant "a Program's active version always has an open block, unless the Program is archived" becomes true by construction. Phase 7's Review inherits a valid data invariant.
Source: Phase 6 kickoff exchange; invariants 3 and 6; `08-training-execution-and-evidence.md`; ARCH-016.
