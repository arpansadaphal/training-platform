### ARCH-045 — Google Gemini added as a second ModelProvider, selected by `MODEL_PROVIDER`
Date: 2026-09-28 | Status: FROZEN | Reversible: Yes, contained to `packages/ai/src/provider/` and `packages/api/src/routers/coach.ts`
Decision: `packages/ai/src/provider/GeminiProvider.ts` implements `ModelProvider` against Google's Gemini API via `@google/genai`, the unified SDK, using the API-key (AI Studio) authentication path. `@google/generative-ai` was rejected — Google deprecated it on 2025-11-30 and its migration guidance is unambiguous ("All new projects must use `@google/genai`"). The `@google/genai` SDK also supports the Vertex service-account path, which this project does not use; the API-key path is what `GEMINI_API_KEY` maps to. Pinned at `^2.24.0` (current stable minor; the SDK's own docs say to pin `< 3.0.0` because v3 requires Node 22+, and this project pins Node 20 via `.nvmrc`). `packages/ai/src/provider/factory.ts` exposes `createProvider()` which selects between `AnthropicProvider`, `GeminiProvider`, and `MockProvider` based on `process.env.MODEL_PROVIDER` (values `anthropic` | `gemini` | `mock`, default `anthropic`), and returns `{ provider, model, providerName }`. `packages/api/src/routers/coach.ts` constructs the provider through `createProvider()`. Env var scheme is additive: existing `ANTHROPIC_API_KEY` stays; new `GEMINI_API_KEY`, `GEMINI_MODEL`, and `MODEL_PROVIDER` are added to `.env.example`, `turbo.json`'s `globalEnv`, and the three local `.env` files. `ANTHROPIC_MODEL` is also added to `.env.example` — it was declared in `turbo.json`'s `globalEnv` but missing from the example file. `GEMINI_MODEL` default per environment: `gemini-3.8-flash` for staging and production; `gemini-3.5-flash` for local dev. Gemini 3.x protocol requirements now handled explicitly in `GeminiProvider`: (1) `functionCall.id` echo — Gemini 3.x returns a unique id on every `functionCall` and requires it echoed on the matching `functionResponse`. (2) `thoughtSignature` echo — Gemini 3.x attaches an opaque `thoughtSignature` to each `functionCall` part and requires it echoed back on the matching part of the next request. Without it, the second tool-loop iteration fails with `400 INVALID_ARGUMENT`. Threaded through `ToolCall.thoughtSignature?: string` and `ModelContentBlock['tool_use'].thoughtSignature?: string`; the orchestrator carries it forward; Anthropic and Mock leave the field undefined.
Rationale: The Phase 8 Coach is architecturally provider-agnostic (ARCH-007) but only had one concrete cloud implementation, which requires paid credits. A second concrete provider satisfies two needs: (a) a functional Coach for Phase 9's end-to-end regression without spending money, and (b) proof that the provider abstraction is a real property. `MockProvider` remains the CI default; `MODEL_PROVIDER=mock` is what makes the Phase 8 network-inspection spec runnable in CI without a key.
Alternatives considered: (a) Skip the second provider and hide the Coach — rejected; the Coach is a delivered Phase 8 surface. (b) Buy Anthropic credits — rejected on the user's zero-cost constraint. (c) Wait for Gemini's tool-calling to mature — rejected; the retry budget absorbs weaker tool-calling. (d) Use the deprecated `@google/generative-ai` SDK — rejected, deprecated. (e) Use `skip_thought_signature_validator` — rejected; silences the error without preserving model state.
Consequence: `MODEL_PROVIDER=gemini` in production is honest but degrades two properties relative to Claude: tool-calling reliability is lower (making the ARCH-042 retry budget more load-bearing), and the confirmation-boundary E2E must hold for whichever model is in use. Any future move back to `anthropic` is a one-line env change. Model strings live in env config per ARCH-007.
Source: Phase 8 close-out; zero-cost constraint in Phase 9 kickoff; ARCH-007; ARCH-042; Google's `@google/generative-ai` deprecation notice (2025-11-30); Gemini thought-signature documentation (2025-11).
