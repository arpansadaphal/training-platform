### ARCH-072 — Exercise cues: a content column, a "(beta)" label until reviewed, none on /check, none in the engine
Date: 2026-11-14 | Status: Accepted (founder direction, 2026-11-14) | Engine unchanged | Reversible: Yes (two additive columns; one UI toggle).
Builds on the product-depth roadmap §5.1 (cue philosophy). Illustrations are a separate, later change (Phase 4).

1. **Data.** `Exercise.cues String[] @default([])` and `Exercise.cuesReviewed Boolean @default(false)` (migration `add_exercise_cues`). Cues are reference data like involvement factors: `packages/db/prisma/cues.ts` is the source of truth, `prisma/seed.ts` writes them onto the existing row by id (it never renames or recreates one) and fails before any write if a cue key is not a seeded exercise or a seeded exercise has none.
2. **Content rules.** 2-3 lines per exercise, at most 90 characters each, second person; setup and range you can check alone, plus a "feel it" line on isolation and machine moves. No safety, medical or outcome language and no form correction (the app cannot see the lifter). Effort is taught once, in the effort picker, so no cue repeats it.
3. **Lint.** `exerciseCues.test.ts` runs every cue through the shared `FORBIDDEN_COPY_PATTERNS` plus `injur*`, `prevent*`, `safe/safely/safer/safety`, `protect*`, `pain*`, `hurt*`, `spine/spinal`, and checks the count, the length and that the keys match the seed exactly.
4. **Beta until read.** Every cue ships as `draft(...)` (`cuesReviewed: false`) and the screen labels it "Cues (beta)". The founder moves an exercise to `reviewed(...)` in `cues.ts` and reseeds; the label then drops to "Cues".
5. **Where cues go.** Only the session screen shows them: collapsed by default, a 44px toggle with `aria-expanded`, in the card header. `getSessionPage` sends cues for the day's own exercises only. `/check` (`check.exercises`) and the Builder (`exercise.listAll`) strip them with `withoutCues`; `/check` shows no cues (founder decision). The analysis engine's reference data is pinned to `{ id, name, movementPattern, equipment }`, so its input is byte-for-byte what it was (tested).
6. **Measured.** Calibration: "no change" for all 15 programs. Coach parity 19/24, unchanged. 375x812 fold, Back Squat, cues collapsed: reps input top 628 to 635 px, Log-button bottom 735 to 742 px (+7). Open, the cues push the log controls below the fold (reps top 830): the lifter chose to read them.
7. **Deploying.** The migration and then `pnpm --filter @training/db exec tsx prisma/seed.ts` must run against production; until the seed runs the columns are empty and the toggle does not render (no cues, no toggle).
