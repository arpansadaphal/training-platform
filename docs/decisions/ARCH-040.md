### ARCH-040 — Phase 6 error-code semantics: ownership/existence failures are NOT_FOUND; state failures on authorized, present entities are PRECONDITION_FAILED; shape/membership violations are BAD_REQUEST
Date: 2026-09-26 | Status: FROZEN | Reversible: Yes, contained to Phase 6 services
Decision: Three tiers of failure, three tRPC codes, applied uniformly: **NOT_FOUND** (entity doesn't exist, OR caller isn't the owner — non-disclosure); **PRECONDITION_FAILED** (entity exists, caller owns it, state doesn't allow the operation); **BAD_REQUEST** (input shape or membership is wrong regardless of state). No new application-level error classes in Phase 6; no new allow-list entries.
Rationale: The kickoff's literal mapping (A3 = NOT_FOUND for archived Program, B6 = BAD_REQUEST for no-workout-days) created two problems. (1) Archived Programs are visible in the UI; NOT_FOUND would be a lie. (2) The two cases share a shape — entity present, caller owns it, state blocks the operation — and unifying them under PRECONDITION_FAILED gives the client one branch.
Alternatives considered: (1) Literal kickoff mapping — rejected. (2) Dedicated `NoActiveVersionError` class — rejected; single call site. (3) PRECONDITION_FAILED for everything — rejected; shape failures aren't state failures. (4) Structured error codes on the wire — left open; message text drives the current UI.
Consequence: Phase 7 and Phase 8 read Phase 6's surfaces the same way: PRECONDITION_FAILED for state-not-ready, NOT_FOUND for ownership/missing, BAD_REQUEST for malformed input. A future phase needing a structured payload adds an application-level TRPCError subclass and extends the errorFormatter allow-list.
Source: Phase 6 kickoff exchange; trpc.ts errorFormatter; ARCH-033.
