### ARCH-050 — E2E (Playwright) runs in CI, whole `e2e/` directory, MODEL_PROVIDER=mock
Date: 2026-09-30 | Status: FROZEN | Reversible: Yes, contained to `.github/workflows/ci.yml` and the provider-gate change in `apps/web/e2e/coach.spec.ts`
Decision: The GitHub Actions `ci` job runs the full Playwright suite (`pnpm --filter web test:e2e`) as its final step, after Build. Job timeout raised from 20 to 30 minutes. Job-level env gains `MODEL_PROVIDER: mock` and `MOCK_SCENARIO: coach-regression`, which activate the `MockProvider`'s scripted Coach scenario (Phase 9 extension to `packages/ai/src/provider/MockProvider.ts`). The `coach.spec.ts` network-inspection test's gate changes from `ANTHROPIC_API_KEY` to `MODEL_PROVIDER === "mock"`, so the test now executes in CI instead of skipping.
Rationale: Before Phase 9, the per-phase E2E specs ran only locally. `pnpm turbo run test` and `pnpm turbo run test:e2e` are distinct task names, so `test` never touched `apps/web`'s Playwright suite. The `coach.spec.ts` network-inspection test — the Phase 8 acceptance test for the Apply-button boundary — was gated on `ANTHROPIC_API_KEY` and skipped in CI without a real key, which meant the central safety invariant of Phase 8 was never asserted in CI. Phase 9 closes both gaps: adding the `E2E (Playwright)` step runs the whole suite, and the mock's `coach-regression` scenario produces the same `simulate_program_change` → `prepare_apply_confirmation` sequence the real Anthropic provider produced in Phase 8, so the boundary assertion runs against a deterministic stand-in. The mock does not bypass the tool loop — the orchestrator still executes every tool against real `CoachToolDeps`; the mock only decides what the model "would have said." This preserves the ARCH-011 / ARCH-018 boundary test's meaning: it asserts that `commitFromSimulation` fires on the click, not on the stream, and the assertion is provider-agnostic.
Alternatives considered: (a) Scope the CI E2E step to `regression.spec.ts` + `coach.spec.ts` only — rejected; running only two specs would make CI a partial regression rather than the full one the phase file requires. (b) Skip the E2E step in CI and run it only against staging — rejected; staging is not yet provisioned, and a regression that runs only on a manually-provisioned environment is a regression that never runs. (c) Keep the `coach.spec.ts` gate on `ANTHROPIC_API_KEY` and add a separate mock-backed spec — rejected; duplicating the test body for two providers creates the two-implementation problem. (d) Bump the job timeout to 45 minutes preemptively — rejected; 30 minutes is what the current suite needs with headroom.
Consequence: CI now runs the full E2E suite on every push to `main` and every PR, using the mock provider and the same ephemeral Postgres service container the earlier steps migrated and seeded. The `coach.spec.ts` network-inspection assertion runs in CI for the first time. The suite runs against a cold Next.js dev server, so the run takes ~5–8 minutes at the current spec count. **CI E2E scope is the full `e2e/` directory, not a subset. Flake response is `test.fixme` + a `PROJECT_STATE.md` note, never a silent scope reduction.** The mock's `coach-regression` scenario is a scripted test double, not a substitute for real-provider validation — staging runs `MODEL_PROVIDER=gemini` and provides that separately. `UPSTASH_REDIS_REST_URL` / `_TOKEN` are deliberately unset in CI so the rate limiter fails open (ARCH-048) and does not introduce false 429s against the E2E suite.
