### ARCH-064 — Public Program Checker: per-IP rate limit category, test-only memory driver, flag-gated API
Date: 2026-11-03 | Status: Accepted | Reversible: Yes. `CHECK_PUBLIC=false` closes the pages and the procedures; the limiter change is contained to `apps/web/middleware.ts`, `apps/web/src/lib/rateLimit.ts` and `rateLimitMemory.ts`.
Addendum to ARCH-048 (which stays FROZEN as written).

Decision:
1. **New category `check`** in the Edge limiter: `/api/trpc/check.analyze`, **20 per hour, sliding window, key `check:ip:<IP>`**. The identifier is always the first `x-forwarded-for` entry, never the session cookie (the Checker is the no-account funnel; a cookie is free to clear). A batch containing `check.analyze` is classified `check` only. Fail-open is unchanged. The 429 body is `{"error": "You've reached the limit for today. Create an account to continue checking programs."}`; other categories keep the generic message.
2. **The limit sits in the Edge middleware, keyed on the procedure name, not inside the procedure.** The assessment is computed through an HTTP tRPC query from `/check/[hash]`, never through `appRouter.createCaller` in an RSC or server action, because in-process calls bypass the middleware. One rate-limit pattern, not two.
3. **Test-only in-memory driver** (`RATE_LIMIT_DRIVER=memory`, `rateLimitMemory.ts`): an in-process sliding window, so the 21st-request behaviour can be exercised in Playwright without Upstash. It refuses to turn on when `VERCEL_ENV=production`. This is the one place the repo substitutes the limiter; it supersedes ARCH-048 alternative (e) ("no test for the limiter") for the `check` category only. The fail-open path needs no fake: CI runs with Upstash unset, and `rate-limit.spec.ts` asserts 25 checks are never refused in that state.
4. **`CHECK_PUBLIC` flag** (`@training/config`, `isCheckPublic`): runtime env read, default false. Off means the `/check` pages 404, `check.exercises`, `check.analyze` and `check.save` throw NOT_FOUND, and the landing link is not rendered. The flag gates the API as well as the pages so a closed launch is closed.
5. **Public analysis is stateless.** `check.analyze` takes a hash (base64url of exercise NAMES, hard size caps, strict decode) and runs the same engine calls as `analysis.previewAnalyze` with goal profile HYPERTROPHY. It writes nothing; `packages/api/src/routers/check.test.ts` asserts it reads PPL 6-day identically to the Builder. `check.save` is the only writer and is a `protectedProcedure`.

Consequence: `turbo.json` globalEnv gains `CHECK_PUBLIC` and `RATE_LIMIT_DRIVER`; CI sets `CHECK_PUBLIC=true` and adds a second small E2E run with the memory driver. No engine, schema or `packages/ai` change.
